# Discovery-chain evals

Do `offer` and `product-brief` produce the documents they promise, and better than a
loose prompt would? The cases live in `../cases/chain/` and are generated by
`build-cases.mjs`, so every case uses the same graders. Edit the generator, run
`node evals/chain/build-cases.mjs`, and commit both.

- `workspace/`: a fictional product (RecallKit, reminders for small dental clinics) with
  a finished `docs/MARKET.md` and the owner's brand notes. No web search is needed, so
  every run starts from the same evidence.
- `controls/`: a known-good and a known-bad offer and brief. `offer-good.md` is also the
  input of the brief cases.

| Case | What it runs |
|---|---|
| `chain-offer-command`, `chain-brief-command` | the skill, by its command |
| `chain-offer-loose`, `chain-brief-loose` | the same request as a loose prompt in Spanish, the way an owner would type it |
| `chain-control-*-good`, `chain-control-*-bad` | the graders alone over a fixed file: good must score 1.00, bad 0.00 |

Run the controls first. A grader is trusted only when it passes the good file and fails
the bad one; the control files carry no hint of which one they are, so the judge can't
read the answer.

```sh
claude plugin eval . --tag chain-control --ablation none --scaffold --trust-plugin --no-publish --judge-model sonnet
claude plugin eval . --tag chain-run --ablation none --scaffold --trust-plugin --no-publish --judge-model sonnet --allow-tools Edit Write -j 2
```

Every case runs with the plugin loaded (`--ablation none`): the commands don't exist
without it, and the loose prompts are the baseline instead.
